## 1. 横切关注点（贯穿所有里程碑）

### 1.1 测试

每个里程碑的交付物**必须附带对应层级的测试**。具体策略见 `testing.md`。硬性要求：

- 新增 `domain/` 逻辑 → 必须有单元测试
- 新增 DB 查询 → 必须有集成测试（`:memory:`）
- 每个 bug 修复 → 必须有回归测试

### 1.2 依赖卫生

每个里程碑结束时执行：

```bash
cargo tree -d          # 检查是否存在重复的 crate 版本（如两份 symphonia）
cargo outdated         # 检查过时依赖
npm outdated
```

**特别注意：** 任何时候不得让 `tauri` 系列升到 3.x alpha。

### 1.3 性能预算核对

M1 起，每个里程碑至少核对一次 `requirements.md` §5.1 的相关指标。

### 1.4 文档同步

架构或需求变更时，同步更新 `architecture.md` / `requirements.md` 并记录变更历史。**文档滞后于代码 = 文档失效。**

## 2. 关键路径与依赖图

```
M0 ──► M1 ──► M2 ──┬──► M3 ──┬──► M4 ──► M5 ──► M6
                   │         │
                   │         └──► （诊断面板可独立完成）
                   └──► （MPRIS 可与 M2 其余部分并行）
```

**串行原因：** M2 的队列是 M3 搜索结果的"动作目标"（搜到后要能加入队列）；M3 的封面是 M4 歌词界面的同层需求；M5 依赖 M1–M4 的稳定接口。
