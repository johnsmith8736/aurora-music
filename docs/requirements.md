# Aurora Music — 需求规格说明

> 文档版本：0.1.0 · 状态：待评审 · 最后更新：2026-10-15
>
> 本文档定义**做什么**与**不做什么**。技术实现方式见 `architecture.md`。

---

## 1. 文档目的与范围

本文档是 Aurora Music 的需求基线。所有后续设计、实现与验收均以本文档的功能编号（`FR-xx` / `NFR-xx`）为准。

**范围内：** 一款面向 Linux 桌面的本地音乐播放器，含资料库管理、播放、歌单与在线来源扩展能力。

**范围外：** 移动端、Web 端、服务端同步、音频编辑、DRM 内容处理。

## 2. 背景与约束

### 2.1 目标运行环境（已实测确认）

| 项 | 实测值 |
|---|---|
| 操作系统 | Arch Linux，内核 7.2.9-arch1-1 |
| 桌面 | KDE Plasma 6.7.5 |
| 显示协议 | Wayland（`XDG_SESSION_TYPE=wayland`） |
| 音频服务 | PipeWire 1.6.9 + WirePlumber 0.5.18，PulseAudio 兼容层可用 |
| 声卡 | `alsa_output.pci-0000_00_1f.3.analog-stereo`，`s32le 2ch 48000Hz` |
| 图形 | Intel UHD (CometLake-H) + NVIDIA Quadro T2000 Mobile（双显卡） |

### 2.2 技术约束

- 技术栈锁定：Tauri 2 / React / TypeScript / Rust / SQLite
- **Tauri 必须停留在 2.x 稳定线**（2.12.4）。crates.io 上 `tauri` 的"最新版本"是 `3.0.0-alpha.5` 预发布版，禁止使用。
- 播放引擎与音乐来源必须解耦，来源实现可插拔

### 2.3 设计原则（不可违背）

| # | 原则 | 落地方式 |
|---|---|---|
| P1 | React 不直接操作音频设备 | 音频仅在 Rust 侧；前端无任何音频 API 调用 |
| P2 | Rust 后端提供明确、可测试的命令接口 | 全部 I/O 经 Tauri command；DB 不对前端暴露 SQL |
| P3 | 音乐来源与播放引擎解耦 | 二者之间只通过 `ResolvedStream` 值对象通信 |
| P4 | 在线来源不得把未验证 URL 直接传入音频引擎 | 类型系统强制：引擎只接受 `ResolvedStream`，其构造函数负责校验 |
| P5 | 所有用户数据必须持久化 | SQLite 为唯一真相源；进程重启后队列/进度/歌单完整恢复 |
| P6 | 先 MVP，后高级功能 | 见 `roadmap.md` 的里程碑门禁 |

## 3. 目标用户与场景

### 3.1 主要用户

拥有本地音乐收藏（数百至数十万首）的 Linux 桌面用户，希望在 Wayland 环境获得现代化播放体验，且不愿被某个商业客户端绑定。

### 3.2 核心场景

| 编号 | 场景 | 成功标准 |
|---|---|---|
| S1 | 首次启动 | 用户指定音乐目录，扫描完成，资料库可见 |
| S2 | 日常播放 | 双击专辑中任意曲目 → 从该曲开始顺序播放，进度条平滑，无卡顿 |
| S3 | 查找 | 输入部分关键词，1 秒内看到跨标题/艺术家/专辑的结果 |
| S4 | 组织 | 新建歌单、拖拽排序、收藏单曲，重启后全部保留 |
| S5 | 断点续播 | 关闭应用再打开，队列与播放位置恢复 |
| S6 | 桌面集成 | 用键盘媒体键控制播放；Plasma 媒体控件显示正确曲目信息与封面 |
| S7 | 边听边看 | 播放时显示同步滚动歌词 |
| S8 | 扩展来源 | 用户自行配置合法在线来源后，可与本地曲目混合排入同一队列 |

## 4. 功能性需求

### 4.1 音乐资料库（Library）

| 编号 | 需求 | 优先级 |

| FR-1.1 | 管理一个或多个音乐根目录，可启用/禁用 | M1 |
| FR-1.2 | 递归扫描，按扩展名白名单识别音频文件 | M1 |
| FR-1.3 | 读取标签元数据：标题、艺术家、专辑、专辑艺术家、音轨号、碟号、年份 | M1 |
| FR-1.4 | 读取技术元数据：时长、采样率、声道数、码率、编码格式、容器格式 | M1 |
| FR-1.5 | 标签缺失时回退到文件名/目录名推断 | M1 |
| FR-1.6 | 增量扫描：文件大小与修改时间未变则跳过 | M1 |
| FR-1.7 | 检测并标记已删除文件（不自动删除用户文件，仅从资料库移除） | M1 |
| FR-1.8 | 扫描进度以节流方式上报；扫描可中途取消 | M1 |
| FR-1.9 | 支持按专辑、艺术家、文件夹、全部曲目浏览 | M1 |
| FR-1.10 | 单文件权限错误不影响整体扫描，记录到错误列表 | M1 |

### 4.2 音频播放引擎（Playback）

| 编号 | 需求 | 优先级 |

| FR-3.1 | 队列为有序列表，当前播放项有明确索引 | M2 |
| FR-3.2 | 追加到队尾 / 下一首播放 / 从队列移除 | M2 |

## 6. 明确的非目标

以下内容**不在本项目范围**，任何实现提案默认拒绝：

| 编号 | 非目标 | 理由 |
|---|---|---|
| NG-1 | 依赖或控制 Spotify 官方客户端 | 与"独立播放器"定位冲突 |
| NG-2 | 绕过 DRM 或解密受保护内容 | 法律风险 |
| NG-3 | 抓取违反服务条款的受版权保护流 | 法律风险 |
| NG-4 | 修改、移动或删除用户的音乐文件 | 数据安全；本应用对音乐目录**只读** |
| NG-5 | 音频编辑、转码、刻录 | 非播放器职责 |
| NG-6 | 在线账户体系、云同步、社交功能 | 显著超出 MVP |
| NG-7 | 移动端 / Web 端 | 见 §1 范围 |
| NG-8 | 内置音乐下载或抓取工具 | 法律风险 |
| NG-9 | 音频可视化 / 频谱分析 | 与核心价值无关，M6 之后再议 |
| NG-10 | 复刻 Spotify 的视觉资产、图标或品牌元素 | 借鉴的是通用交互范式，不是美术资源 |

> **关于"借鉴 Spotify 交互"的边界：** 本项目借鉴的是行业通用的播放器交互范式——左侧导航、底部常驻播放条、队列侧栏、卡片式专辑网格。这些属于通用 UI 模式。**不得**复制其图标、插画、字体、Logo 或任何专有视觉资产。

## 7. 法律与合规边界

1. **本地文件：** 应用仅读取用户已有的音频文件，不修改、不移动、不删除，不绕过任何访问控制。
2. **在线来源：** 适配器只能对接**公开的、经授权的、条款允许的**接口。每个适配器实现必须附带其合规依据说明（API 文档链接、服务条款相关条款）。
3. **不内置内容：** 应用不携带任何音乐内容，不提供下载或翻录能力。
4. **凭据：** 用户凭据仅存储于本机，不上传、不记录到日志。
5. **元数据获取：** 若接入元数据服务，须遵守其速率限制与署名要求。

## 8. 术语表

| 术语 | 含义 |
|---|---|
| **曲目 (Track)** | 资料库中的一条音频记录，本地或在线 |
| **来源 (Source)** | 曲目的提供方；`local` 为内置来源 |
| **候选 (Candidate)** | 来源搜索结果中的条目，尚未解析出可播放地址 |
| **已解析流 (ResolvedStream)** | 通过校验、可交给播放引擎的音频地址及其元信息 |
| **队列 (Queue)** | 当前播放的有序曲目集合 |
| **上下文 (Context)** | 队列的来源（专辑、歌单或手动添加），影响"下一首"语义 |
| **扫描会话 (Scan Session)** | 一次资料库扫描的完整记录及其统计 |
| **置换 (Permutation)** | 随机播放所用的固定顺序映射 |

## 9. MVP 验收标准

MVP（里程碑 M1 + M2）完成的判定标准：

| # | 验收项 | 验证方式 |
|---|---|---|
