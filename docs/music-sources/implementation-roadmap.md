### 验收标准

- [ ] `LocalMusicSource` 通过全部 CT-1 ~ CT-10 契约测试

## S4 — 队列/播放器跨来源扩展

**这是唯一需要修改现有播放链路类型的阶段。**

### 前置条件

| # | 条件 | 状态 |
|---|---|---|
| S3 | 完成 | — |
| D-5 | 接受对 `AudioSource` / `QueueEntry` 的修改范围 | **待决策** |

### 交付物

对应 `interface-design.md` §7.2 的 E-1 ~ E-4：

| # | 内容 | 影响文件 |
|---|---|---|
| 4.1 | `AudioSource` → `ResolvedStream` | `domain/ports.rs`、两个引擎、`playback_service.rs` |
| 4.2 | `QueueEntry` 增加来源字段 | `domain/queue.rs`、`library_service.rs`、前端 |
| 4.3 | `track_id` 改为可表达来源 | 队列、历史、播放服务 |
| 4.4 | 数据库迁移 | `infra/db/schema.rs` |
| 4.5 | 数据库迁移 | `schema.rs` v3 |
| 4.6 | UI：在线曲目与本地曲目混合队列 | 前端队列面板 |

### 验收标准

- [ ] 本地播放行为**完全不变**（`real_playback.rs` 全部通过）
- [ ] 本地 + 在线曲目可在同一队列中交替播放
- [ ] **队列表不含任何 URL**（E-4）
- [ ] 从持久化队列恢复时**重新解析**（E-3）
- [ ] 来源禁用期间播放到该来源曲目 → 跳过并提示，不崩溃
- [ ] 现有 105 个测试全部仍通过

### 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 改动播放链路引入本地回归 | 高 | 现有 `real_playback.rs` 是安全网；改动前先确认其覆盖完整 |
| `track_id: i64` 的改动面广 | 中 | 可考虑用枚举而非全局替换，减少改动面 |
